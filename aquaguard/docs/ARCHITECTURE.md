# Architecture

**Mode A** modular monolith: Next.js frontend · FastAPI backend · offline Python ML pipeline. All water maths lives in one engine layer.

```
external sources ──► ml/fetch_*.py (adapters) ──► data/raw/ ──► ml/build_geo.py, process_weather.py, grace_trend.py
                                                               │
                                                               ▼
                         data/processed/ ──► ml/build_db.py ──► SQLite data/aquaguard.db  (+ data/sample snapshot)
                                                               │
ml/build_features → train_scarcity → evaluate → predict → explain_shap → project_demand → ml/artifacts/*.json, *.joblib
                                                               │
backend/app: services/data_access ─► services/inputs ─► engine/* (water_balance, scenario, fao56, flow_sim, risk, optimizer)
             services/ml_artifacts (reads artifacts; re-runs models for scenarios; never trains)
             services/regional (one region×scenario computation shared by every module)
             services/alerts, services/copilot
             routers/* (one per module + health, regions, sources)  ──► /api/* (OpenAPI at /api/openapi.json)
                                                               │
frontend: lib/api (typed client; mock mode) ─► lib/store (Zustand: selectedRegion, activeScenario; URL sync)
          app/<module>/page.tsx ─► components/{charts (Plotly, D3 Sankey), maps (MapLibre), three (R3F), copilot, ui}
```

## Layers

| Layer | Path | Notes |
|---|---|---|
| Ingestion adapters | `ml/fetch_openmeteo.py`, `ml/fetch_static.py`, `ml/import_bwdb.py`, `ml/grace_trend.py` | One adapter per source; retry/backoff; retrieval times recorded |
| Cleaning | `ml/build_geo.py`, `ml/process_weather.py` | Complete months only; 1991–2020 climatology |
| Storage | `backend/app/db/schema.sql`, `ml/build_db.py` | SQLite; sample snapshot for offline mode |
| Engines | `backend/app/engine/` | Pure functions, unit-tested; parameters from `config/parameters.yaml` |
| Services | `backend/app/services/` | Data access with fallback, ML artifacts, regional runs, alerts, Copilot |
| API | `backend/app/routers/`, `schemas/` | Pydantic models are the contract; every number is a `Measure` |
| Frontend | `frontend/` | App Router; maps/3D/charts are client-only and lazy-loaded |

## Global state

Zustand store (`frontend/lib/store`): `selectedRegion`, `activeScenario`, `lastUpdated`, mirrored in the URL (`?region=dhaka&rain=-20&temp=1&demand=10&gw=-20&eff=0.75&loss=30`). Every page reads region and scenario from the store, so applying a scenario in the What-if Simulator changes the Command Center, Explorer, Prediction Lab, Sankey and Copilot at once.

## One calculation, one place

`services/regional.run(region, scenario)` produces the division balances used by `/overview`, `/budget`, `/scenario/run`, `/map/layers`, `/predictions/*`, `/alerts` and the Copilot. Agricultural demand is always `engine.fao56.agricultural_demand_monthly`, the same Kc curve and effective-rainfall rule the Irrigation Advisor uses. `tests/test_consistency.py` asserts that baseline Command Center = Sankey = What-if totals.

## Contract

Pydantic models in `backend/app/schemas/` → OpenAPI (`docs/openapi.json`) → TypeScript types (`frontend/lib/types/api.d.ts`, generated by `npm run gen:api`). Mock JSON for every endpoint (`frontend/public/mocks/`) is captured from the API running on the sample snapshot; `NEXT_PUBLIC_API_MODE=mock` serves it without a backend.
